## 1. Зачем (проблема)

Пользователь тонет в задачах и идеях: мысли обгоняют действия, списки не ведутся или ведутся и бросаются. Ключевая боль — не объём дел, а три вещи:

1. **Нулевой порог входа отсутствует** — записать задачу лень/долго, поэтому всё живёт в голове и давит.
2. **«Щели»** — провалы по 30–90 минут между намерением и действием (прокрастинация, ступор).
3. **Нет внешней структуры** — никто не спрашивает «ну что, сделал?», нет ритуалов начала и конца дня.

**Формула продукта:** вывалил кашу → приложение само разобрало → предложило план дня → пинает в течение дня → вечером подводит итог без морализаторства.

## 2. Принципы (чем отличаемся от рынка)

| Принцип | Чего не хватает конкурентам |
|---|---|
| Capture за 5 секунд: текст или голос, без структуры | У большинства ввод — это форма с полями |
| AI **предлагает** план, человек **утверждает** | Motion переставляет всё без спроса — главная жалоба юзеров |
| Ритуалы: утренний план + вечерний итог | Есть только у Sunsama, и без AI |
| Проекты с контекстом: «клип → дедлайн → критический путь» | Никто не понимает структуру проектов |
| Тон — тренер, а не бухгалтер: без стрика-шейминга | У всех стрики, которые наказывают за срыв |

## 3. Сценарий пользователя (core loop)

1. **Выгрузка:** открыл → сразу поле ввода (как чат). Пишешь/диктуешь кашей. AI разбирает в: задачи / идеи (парковка) / события / привычки. Показывает, как понял, — одна кнопка «ок».
2. **Утро (5 мин):** приложение показывает предложенный план дня: 1–3 фокуса + мелочи, с учётом дедлайнов и календаря. Свайп — принять/перенести/убрать.
3. **День:** локальные пуши — не «напоминалки», а следующий шаг: «Хореограф: напиши Соне — 10 мин». Один активный шаг за раз.
4. **Вечер (5 мин):** итог: что сделано / что переезжает / без самобичевания. «Сделано 2 из 3 — норм. Завтра берём хореографа первым».
5. **Неделя:** воскресный обзор — проекты, дедлайны, что в парковке созрело.

## 4. Экраны MVP

- **Захват** (главный, открывается по умолчанию) — поле ввода. MVP — только текст: голос закрывает системная диктовка на клавиатуре iOS.
- **Входящие (Inbox)** — список всех захватов (новые сверху, необработанные отмечены). Ручной разбор захвата: «В задачу», «В парковку», «В шаг проекта», «Удалить»; при разборе `processed = true`. Вход — тап по счётчику «Записано сегодня: N» на экране Захвата. AI-разбор (v1) будет работать с этим же списком.
- **Сегодня** — план дня: фокусы, мелочи, расписание блоками. Тап по задаче — редактирование. Выполненные задачи в списке не показываются: внизу строка «Выполнено · N» — папка со всеми выполненными задачами (сортировка по дате выполнения, свежие сверху).
- **Проекты** — список проектов: дедлайн, следующий шаг, статус.
- **Детали проекта** — редактируемые поля проекта + список шагов: добавление (название, опциональный дедлайн), отметка «выполнен», правка дедлайна, удаление.
- **Дедлайны и напоминания** — дедлайн (задача, шаг, проект) включает дату и время. У каждого дедлайна — список напоминаний с явными датой и временем (добавить/изменить/удалить); при установке дедлайна создаются три авто-напоминания: за 3 дня, за 1 день, за 1,5 часа (попавшие в прошлое пропускаются). Сортировка списков: с дедлайном — по времени дедлайна (раньше выше), без дедлайна — в конце.
- **Парковка** — идеи и «когда-нибудь» (чтобы голова отпускала).
- **Вечерний итог** — свайп-разбор дня.

## 5. Модель данных (сразу с закладкой под веб/синхронизацию)

- `User` (id, настройки, таймзона)
- `Capture` (id, raw_text, created_at, processed: bool)
- `TaskItem` (id, project_id?, title, notes, deadline?, priority, status, estimate_min?, source_capture_id, completed_at?, reminders: [Reminder])
- `Project` (id, title, deadline?, status, next_step?, context_notes, reminders: [Reminder])
- `Habit` (id, title, frequency_rule, active)
- `DayPlan` (id, date, items: [task_id, time_block, approved: bool])
- `Idea` (парковка) (id, title, notes, created_at, status)

Шаг проекта — это `TaskItem` с заполненным `project_id`: название, опциональный дедлайн (можно менять), статус (закрывается при завершении). Напоминания по шагам — через локальные пуши.

Дедлайн (задача, шаг, проект) включает дату и время. `Reminder` (встроенная структура в `TaskItem` и `Project`): (id, fire_at, is_auto). При установке дедлайна создаются авто-напоминания (−3 дня, −1 день, −1,5 часа; прошедшие пропускаются); при изменении дедлайна авто пересчитываются, ручные сохраняются; при снятии дедлайна список очищается. Напоминания — локальные пуши на каждый `fire_at`; отменяются при выполнении и удалении. Правила действуют и для собственного дедлайна проекта.

Принцип: всё рождается из `Capture` — сырой ввод никогда не теряется, AI-разбор всегда можно пересмотреть.

## 6. Технический подход

- **Платформа:** **только iOS** (личный iPhone Егора). Публикация в App Store НЕ нужна.
- **Стек:** нативная разработка — **SwiftUI + SwiftData** (решение от 23.11: Expo отвергнут, кроссплатформенность не нужна, приоритет — полноценные локальные уведомления и простота отладки в Xcode).
- **Доставка на устройство:** сборка через Xcode на свой iPhone с бесплатным Apple ID (Personal Team). Сертификат живёт 7 дней → **еженедельный ритуал пересборки** (2 минуты, кабель). К v1 оценить переход на Apple Developer $99/год (TestFlight, 90 дней без пересборки).
- **БД на MVP:** SwiftData локально (без бэкенда).
- **AI-разбор:** вызов LLM API (структурированный JSON: массивы задач/идей/событий). На MVP — один эндпоинт-прокси или прямой вызов с ключом.
- **v3 (потом):** бэкенд на Supabase (Postgres + Auth + Realtime) → веб-версия на React. Схема БД из п.5 мигрирует 1:1.

## 9. Нефункциональные требования к MVP

- Время от «открыл» до «записал мысль»: **≤ 5 секунд**.
- Оффлайн-первое: всё работает без интернета, кроме AI-разбора (тогда задача просто сохраняется сырой).
- Тёмная тема по умолчанию (ночной пользователь, ага).
